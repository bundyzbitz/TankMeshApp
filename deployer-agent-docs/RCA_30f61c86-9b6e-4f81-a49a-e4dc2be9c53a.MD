# RCA — Android AAB store build never completed (ble-tank-monitor)

(Note: this concerns a STORE build pipeline_run `db1j8rjtgh0s7395o3qg`, not the deploy run this file is keyed under. Backend deploy run 30f61c86 is live and healthy — unrelated.)

## User symptom
Android build submitted (exit 0) but no new AAB/APK artifact appeared; panel still shows a 2-month-old build as newest completed.

## What the evidence shows
The "Publish to Play Store" attempt at 2026-10-05 05:23 created TWO Android pipeline runs (by design — one APK, one AAB):

- **APK run** `db1j8rbtgh0s7395o3p0` — Build Type: apk — EAS build `21d4cc8a-38be-48cd-aadd-a7ebe3b7339f` — **SUCCEEDED** (webhook returned artifact URL).
- **AAB run** `db1j8rjtgh0s7395o3qg` — Build Type: app-bundle — EAS build `6bb0bc6d-59c5-456d-8a20-46ce7271c9d2` — **FAILED**: `build failed: timed out after 2h0m0s with no response from EAS`.

### AAB run details (Cloud Build side — all healthy)
- Keystore downloaded, deps installed, backend URL rewritten to https://ble-tank-monitor.emergent.host
- versionCode incremented 108 → 109
- Uploaded to EAS, fingerprint computed
- `eas build --platform android --profile app-bundle` returned **exit code 0**
- Build ID `6bb0bc6d...` recorded; webhook already registered
- Pipeline then waited for the EAS webhook to deliver the artifact URL — callback NEVER arrived within 2h → run timed out.

## Root cause
Build was submitted to EAS successfully. Emergent waits for EAS to call its webhook with the finished artifact. For the AAB that callback never came within 2h0m, so Emergent timed the run out. The APK submitted one second earlier to the SAME Expo account/project got its webhook back and succeeded — proving Emergent-side webhook routing works. This isolates the problem to the AAB build ON EAS's side: it either errored during the native Android build, or sat queued/stalled past the 2h timeout, so no success webhook fired.

## What could NOT be determined from available tools
Actual EAS-side state (QUEUED / IN_PROGRESS / ERRORED / FINISHED) and any native Gradle/compile error are only visible on Expo's servers. Deployer tools only see Emergent's pipeline side. Read from the Expo build page:
https://expo.dev/accounts/emergent-em-user-56875da4-c8c2-45d4-9123-90b9b2f820a4/projects/ble-tank-monitor/builds/6bb0bc6d-59c5-456d-8a20-46ce7271c9d2

## APK vs AAB question
No config change. The 2-month-old runs (`da6q1di...`, `da6ookq...` pairs) and today's both create an APK + AAB pair every time. This attempt did too — the APK (`21d4cc8a`) succeeded. An APK artifact from this run already exists; only the AAB timed out.

## Minor non-fatal note
AAB log line `script: line 199: expo: command not found` appeared during STEP 5 (app.json fix). Non-fatal — the resolved Expo config was still written and the build submitted successfully afterward. Not the cause of the timeout.

2. Before re-triggering, open the Expo build URL above to confirm whether `6bb0bc6d` ERRORED (native compile error → needs a source fix) or just stalled in queue (re-trigger is enough).
3. An APK from this same attempt (`21d4cc8a`) already completed successfully and is available now.
